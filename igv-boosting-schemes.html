IGV Business Development · Boosting

iGV 代练业务开发方案

以 Diablo 4 为原型验证：卖家竞价（方案一）· 官方精选（方案二）· 买家定价（方案三）——方案说明与可点击买家端原型
面向市场 EU/NA 原型：中英双语，均到支付前
方案选择

三套方案骨架相同，差异只在供给与定价：谁定价、谁主动。方案一参考 Eldorado——买家不报价，卖家竞价；方案二参考 Overgear——平台自营 / 精选，标品明码标价；方案三参考代练通——与方案一相反，买家自己定价，卖家在大厅抢单。

倾向方案一与方案三，且两者可以并存。方案一对买家门槛更低，只需描述需求，卖家竞价带来价格竞争，转化率可能更高；方案三对买家门槛略高，要自己定价和设保证金，但对卖家更友好——卖家挑单、按买家给的价接活、不用逐单压价，能留存更多卖家。两者共用同一批卖家与同一套担保底层，可以做成同一品类下的两个入口。方案二作为后续的“官方精选”信任层，用于高客单、高信任需求。

方案一 · 对标 Eldorado

买家发需求 → 卖家竞价 → 买家挑报价

买家下单前不显示价格，约 5 分钟收到报价，按评分 / 时效 / 交付方式 / 价格挑选。

买家门槛最低，竞价压价，转化率可能更高。
方案三 · 对标代练通

买家自定价 + 保证金发单 → 卖家抢单

买家填价格、时限和保证金要求，预存代练费后进入接单大厅，卖家主动抢单。

卖家最友好，能留存更多卖家；买家掌握定价权。
方案二 · 对标 Overgear

目录 → 详情页配置算价 → 直接下单

平台自营或精选少量团队，统一 SOP，固定价 SKU，所见即所得。

质量可控但重资产，适合作为后续信任层。
并存的关键

同一卖家池，两种定价入口

卖家后台同时看到“请求实时流”（方案一）与“接单大厅”（方案三）；方案一的成交价反哺方案三的参考价。

详见“方案一 + 三并存设计”。

ESCROW

担保交易

买家付款后资金由平台托管，确认交付后才放款；发生争议时冻结、可退款。这是所有代练交易的信任基础。

ACCOUNT SAFETY · IGV 核心差异化

账号安全分级（交付方式）

自己上号 / 陪打（self-play）：买家全程控号，与 booster 组队完成，不交出登录信息，风险最低，服务类默认。交易化交付（trade）：装备 / 材料 / 成品号以道具 / 账号交易形式交付，平台担保。上号代打（piloted）：需强实名 KYC、资金担保、可要求直播 / 录屏留证，风险最高，作受控选项。

优先前两者，契合欧美对“交号 / 共享密码”的敏感与合规——这是相对纯 piloted 代练站的最大区隔。
GOODS × SERVICE

货服打通

成品号 ≈ 账号交易、装备材料 ≈ 道具交易；代练与 IGV 现有交易生态互通，买家可在“找人代练”与“直接买现货”之间切换。

PLATFORM

多语种 SEO · 信誉 / 纠纷 / 分账

沿用 14 语种能力，标品品类做多语言落地页，抢 EU/NA 搜索流量；评价与完成率、争议仲裁、卖家分账与提现由平台统一提供，可复用现有交易基建。

SCHEME 1

方案一 · C2C 撮合市场（卖家竞价）

把 IGV 的 C2C 交易能力延伸到“服务”：买家发需求 → 第三方 booster 竞价接单 → 平台担保撮合。对标 Eldorado。

供给侧：卖家怎么来、怎么接单

入驻与 KYCbooster 注册成为卖家，完成实名认证（提供 piloted 交付的要求更严），声明可服务的品类、语言、平台（PC / 主机）
不维护固定价卖家不需要预先建 SKU / 填价目；看到匹配的买家请求后逐单报价
接单方式卖家在后台看到“请求实时流”，对匹配请求出价（价格 + 时效 + 交付方式 + 留言），并可与买家实时聊天

定价机制：纯竞价

买家下单前不显示价格，只显示“卖家竞价、约 5 分钟出报价”。买家发出请求 → 系统通知匹配卖家 → 卖家逐个报价 → 买家在报价列表按评分 / 时效 / 交付方式 / 价格挑选（可先聊再定）→ 接受报价即锁价。价格由竞争产生，通常更低；代价是下单前无价格锚，用竞争与出价速度对冲。

买家端到端流程

STEP 1

配置需求

进入品类 → 参数配置器填需求（等级段 / 职业 / Boss / 次数 / 难度…）或用 Custom Request 自由描述；选交付方式。

STEP 2

等待报价

点“获取报价” → 撮合等待态，实时计数：已通知 / 已查看 / 已报价。

STEP 3

比价挑选

报价列表（RECOMMENDED / Trusted / Fastest），看评分、评价数、时效、价格，可聊天、可多方比价。

STEP 4

接受并付款

结算页：订单信息、交付方式与账号安全提示、支付方式、费用汇总。付款后卖家交付 → 买家确认 → 放款。

交付与账号安全 · 平台职责

服务类默认自己上号 / 陪打；装备 / 成品号走交易化交付；上号代打作受控选项（强 KYC + 担保 + 留证），交付方式随品类自动变化。平台负责请求分发与撮合、资金担保托管、评价与信誉、纠纷仲裁、分账与提现、反欺诈风控。

IGV 复用 / 新增

✓ 可复用
  • 担保交易、纠纷、评价体系
  • 账号 / 道具交易履约与货服打通
  • 14 语种 SEO、买家账户与支付
＋ 需新增
  • 请求—竞价撮合引擎（分发 / 出价 / 报价列表）
  • 卖家接单后台 + 实时聊天
  • 服务类订单状态机（接单→进行→交付→确认）
  • booster KYC 与交付方式合规

关键设计点

  • 双边冷启动：先聚拢一批 booster 供给（可从现有卖家 / 合作代练团队导入），再放量买家需求；首批可用“官方兜底”接单避免空窗。
  • 账号安全治理：piloted 强 KYC + 担保 + 留证；产品上鼓励 self-play / trade。
  • 质量参差：靠完成率、争议率、评分驱动的信誉体系与排序（RECOMMENDED）约束。

利弊

优势
  • 最贴合 IGV C2C 基因，复用交易 / 担保基建
  • 轻资产、起量快、长尾广
  • 竞价价格低、货服打通天然
劣势
  • 双边冷启动
  • 履约质量 / 账号安全依赖第三方
  • 标品化弱、体验参差；piloted 合规需治理

适合品类 · 上线所需

升级 / 刷本 / Boss（标品高频）优先；装备材料并入道具交易；Custom 自定义需求只能走这条（非标无法预先定价）。工程：撮合引擎、卖家后台、实时聊天、订单状态机、结算分账。运营：booster 招募与 KYC、信誉 / 排序规则、纠纷 SOP、首批供给冷启动。

SCHEME 2

方案二 · 官方精选目录（明码标价）

平台自营或精选少量代练团队，统一 SOP，商品化为固定价 SKU；买家浏览目录 → 详情页配置 → 直接下单。对标 Overgear。

供给侧：卖家怎么来、怎么上架

精选 / 自营平台签约或自建少量代练团队，需通过资质审核，约定 SLA（时效 / 质量 / 售后）
上架 = 填费率卡为每个服务建商品，填基础价 + 可配置属性的加价规则。例：升级 = 基础价 + 等级段 / 巅峰 / 硬核 / 加急的价格增量；Boss = 每次单价 × 次数 + 难度增量。这套费率卡是明码标价能成立的基础
质量可控统一 SOP、质检、售后保障（如 45 天）

定价机制：明码标价 + 详情页配置算价

目录卡显示“低至 $X”（起价）；商品详情页有配置面板，买家选属性（等级段 / 职业 / 难度 / 数量 / 交付方式…）→ 按费率卡实时算出确切价。所见即所得，决策快、客服压力小。

买家端到端流程

STEP 1

浏览目录

左侧分类树 + 商品卡（起价 + 卖点 + Sold by）。

STEP 2

详情页配置

卖点、How it works、右侧配置面板（选属性 → 动态算价）+ 交付方式。

STEP 3

直接结算

“立即购买并结算”，不经购物车；订单项含所选配置摘要。

STEP 4

按 SOP 交付

付款后按 SOP 交付 → 买家确认 → 平台放款。

交付与账号安全 · 平台职责

服务类可选自己上号 / 上号代打（piloted 可给折扣）；装备 / 成品号走交易化交付，详情页显示对应账号安全提示。平台负责选品与 SKU / 费率维护、质检、SLA 管理、售后、担保托管、结算。

IGV 复用 / 新增

✓ 可复用
  • 担保、支付、结算
  • 账号 / 道具交易履约、货服打通
  • SEO（每个 SKU = 可索引落地页，天然友好）
＋ 需新增
  • 商品 / SKU + 费率卡管理后台
  • 配置器 → 算价引擎
  • 精选卖家签约与质检流程、SLA / 售后系统
  • 自营 / 精选运营团队

关键设计点

  • 重资产：需自建或深度签约代练运营、排班、质检；起量慢。
  • SKU 维护：D4 每约 3 个月赛季更新，需同步刷新 SKU / 文案 / 价格。
  • 与市场的张力：若同时有方案一 / 三，官方自营会与第三方卖家竞争，需用“官方 = 质量 / 信任层”做定位区隔。

利弊

优势
  • 质量 / 时效 / 账号安全可控，品牌信任强
  • 明码标价 + 详情配置，决策快
  • 高价值需求（成品号 / BD）易做成高客单标品；SEO 友好
劣势
  • 重资产、起量慢、扩品类慢
  • SKU / 费率维护与赛季运维成本高
  • 与平台“撮合”定位有张力

适合品类 · 上线所需

高价值 / 高信任需求（成品号毕业、BD、指定神话装），或作为市场里的“官方精选”信任层。工程：SKU + 费率卡后台、配置算价引擎、商品详情页、SLA / 售后、SEO 落地页。运营：选品、签约 / 自建代练团队、SOP + 质检、赛季 SKU 刷新、售后客服。

SCHEME 3

方案三 · 自由发单 + 接单大厅（买家定价 · 卖家抢单）

买家自己定价格 + 保证金要求发单，预存后进入接单大厅，由卖家主动抢单。对标代练通（个人向，砍掉贩子功能）。
与方案一的区别

两套都是 C2C 市场，但定价机制相反：方案一是“买家发需求 → 卖家竞价压价 → 买家从报价里挑”；方案三是“买家自己定价 + 保证金发单 → 进大厅 → 卖家主动抢单”。方案三适合心里有预算的个人买家（不用等竞价），并用保证金给账号安全和时效上双保险。

供给侧：卖家怎么接单

接单大厅卖家浏览订单池，按游戏 / 价格 / 难度筛选，挑自己能做的主动抢单。价格太低就没人接，由供需自然出清
缴保证金接单接单时卖家缴纳买家设定的安全保证金 + 效率保证金作押金；砸号 / 超时会扣。用押金替代部分信誉约束，尤其保护账号安全
频道分层优选订单（平台认证实力打手可接）/ 公共频道（所有卖家）/ 陪练专区。砍掉代练通里面向工作室 / 贩子的内部频道、打手组
双击接单卖家在大厅双击任意订单行，弹出接单窗口（订单详情 + 说明 + 要求 + 联系方式），可跟发订单 / 与发单者议价 / 接手

定价机制：买家自主定价 + 保证金

价格不由竞价产生，而是买家发单时自己填（订单价格 + 时限）；同时买家设定要求接单卖家缴纳的安全保证金 / 效率保证金。所见即所定，买家掌握定价权；是否有人接由卖家在大厅自行判断。

买家端到端流程

STEP 1

填写发单

游戏 / 区服、订单任务、交付方式（陪练不交号 / 代练上号）、订单价格（自己定）、时限、安全 + 效率保证金、说明与要求、发布频道、质量门槛。

STEP 2

预存并发布

预存代练费（冻结）并发布 → 直接进 IGV 现有结算页 → 付款。

STEP 3

卖家抢单

订单进入接单大厅 → 卖家缴保证金抢单。

STEP 4

验收放款

进度查看 → 买家验收 → 平台放款；砸号 / 超时扣卖家押金。

交付与账号安全 · 平台职责

发单页直接内建两档：陪练 / 不交号（self-play，默认）与代练 / 上号（piloted，需强实名 + 缴押金 + 可留证）。代练模式下，账号信息在担保成交后通过安全通道提供，不在发单表单里明文填写。平台负责订单池撮合与频道分发、预存资金托管、保证金托管与扣罚规则、进度 / 验收、评价信誉、纠纷仲裁、分账结算。

IGV 复用 / 新增

✓ 可复用
  • 担保托管、支付、结算分账
  • 账号 / 道具交易履约、货服打通
  • 评价 / 纠纷、14 语种 SEO、买家账户
＋ 需新增
  • 买家发单页（自定价 + 保证金）
  • 接单大厅（订单池、筛选、频道）+ 双击接单窗口
  • 保证金托管与扣罚引擎
  • 抢单并发控制、订单状态机

关键设计点

  • 定价合理性：买家定价过低会没人接、留在大厅；可给“参考价区间 / 建议价”引导，避免大量僵尸单。
  • 保证金规则：明确安全 / 效率押金的扣罚条件与仲裁标准，是这套模式信任的核心。
  • 抢单公平与并发：同一单可能多人想接，需处理并发抢单、避免“接了不做”；可用信誉门槛（拒绝低完单卖家）约束。
  • 个人向裁剪：去掉代练通面向工作室 / 贩子的批量管理、加价导出、内部频道 / 打手组、桌面客户端，保持消费级体验。

利弊

优势
  • 买家掌握定价权，适合有预算的个人，不用等竞价
  • 保证金给账号安全 + 时效双保险，契合 IGV 定位
  • 卖家抢单体验轻、供给响应快；对卖家友好，利于留存
劣势
  • 买家定价不合理会产生僵尸单、匹配效率低
  • 保证金 / 扣罚规则与仲裁较重，需完善
  • 抢单并发与“接了不做”需治理

适合品类 · 上线所需

几乎全品类都可（买家能描述清楚 + 给出价格即可），尤其适合心里有明确预算的个人需求；陪练类天然走“不交号”。工程：发单页、接单大厅 + 接单窗口、保证金托管 / 扣罚引擎、抢单并发控制、订单状态机、结算。运营：保证金与扣罚 SOP、纠纷仲裁标准、参考价引导、卖家信誉门槛、频道运营。

COMBINE

方案一 + 方案三并存设计

两种定价机制面向不同的买家心态：没想好价格的买家走竞价，心里有预算的买家走发单。底层、卖家池、交付方式全部共用。
① 买家入口

同一品类页，两个按钮

品类页配置完需求后，主按钮“获取报价”（方案一），次按钮“我来定价发单”（方案三）。配置器填好的参数直接带入发单页，买家不用重填。

默认引导竞价：门槛低、转化高；有预算的买家一键切到发单。
② 卖家工作台

一个后台，两条接单流

卖家在同一工作台看到“请求实时流”（去报价）与“接单大厅”（去抢单），共用 KYC、信誉、保证金账户与提现。

留存逻辑：不想压价的卖家可以只在大厅挑单，降低流失。
③ 价格互哺

方案一的成交价 → 方案三的参考价

方案一沉淀的真实成交价，按品类与参数生成方案三发单页的“参考价区间 / 建议价”，直接解决方案三的僵尸单问题。

闭环：竞价产生价格信号，发单利用价格信号。
④ 兜底流转

两种订单可以互相转化

方案三订单在大厅超时无人接 → 提示买家调价，或一键转为方案一的报价请求；方案一请求久无满意报价 → 可转为发单。

目的：让每笔需求都有出口，减少流失。
并存要治理的问题

① 卖家注意力分流：两条接单流同时存在，冷启动期供给不足时会互相稀释，需要按品类控制两个入口的开放节奏。② 规则复杂度：保证金只存在于方案三，卖家和买家要清楚两种订单的权责差异，商品页与工作台需要统一的订单类型标识。③ 买家选择困难：入口文案要讲清差别——“让卖家来报价” vs “我出价，等卖家来接”，避免买家在两个按钮之间犹豫。
